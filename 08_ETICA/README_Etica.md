# Expediente Ético - Proyecto Fabro Gym

Repositorio documental del expediente de aprobación ética del proyecto académico **Fabro Gym: Sistema de gestión administrativa y operativa para un gimnasio**, desarrollado en la asignatura **ISR-401 - Ingeniería de Requisitos** de la Carrera de Ingeniería de Software de la Universidad Técnica Estatal de Quevedo (UTEQ).

> **Importante:** este repositorio contiene documentación académica y formularios editables. Antes de publicar o compartir cualquier archivo, deben eliminarse firmas, números de identificación, datos de contacto, audios, videos y demás información que permita identificar a participantes o colaboradores.

## Descripción del proyecto

Fabro Gym es una propuesta académica orientada al levantamiento, análisis, especificación y validación de requisitos para un sistema de gestión de gimnasios. Durante esta etapa se estudian procesos administrativos y operativos mediante entrevistas, encuestas anónimas, observación autorizada, actividades de Design Thinking y validación de mockups.

El alcance del expediente es exclusivamente **académico y documental**. No implica la instalación, entrega, contratación ni puesta en producción de un sistema informático en el establecimiento colaborador.

## Objetivo del repositorio

Centralizar y mantener organizada la documentación necesaria para:

- solicitar la revisión y aprobación ética institucional;
- establecer las condiciones de participación de personas y establecimientos colaboradores;
- definir los instrumentos de recolección de información;
- documentar el tratamiento, almacenamiento, retención y eliminación de datos;
- gestionar riesgos éticos, privacidad y confidencialidad;
- demostrar el cumplimiento de la Ley Orgánica de Protección de Datos Personales del Ecuador;
- conservar la trazabilidad de versiones y evidencias del proyecto.

## Documentos de Categoría A

La carpeta `Categoria_A` contiene controles adicionales relacionados con el dominio potencialmente sensible del proyecto:

- protocolo de disociación y privacidad;
- declaración de uso de datos sintéticos;
- aval específico del establecimiento deportivo;
- aplicación de la LOPDP a datos sensibles;
- declaración de no aplicabilidad de imágenes y biometría.

La clasificación **Categoría A** responde a que un sistema de gimnasio podría manejar información sensible en un entorno real. Sin embargo, durante este proyecto académico se excluye el uso de datos reales de salud, biometría, medidas corporales, pagos identificables y registros internos de clientes o trabajadores.

## Principios éticos y de privacidad

El proyecto aplica los siguientes principios:

- participación voluntaria y consentimiento informado;
- finalidad académica específica;
- minimización de datos;
- uso preferente de datos sintéticos o previamente disociados;
- acceso restringido a evidencias autorizadas;
- separación entre consentimientos y transcripciones;
- confidencialidad de participantes y establecimientos;
- conservación limitada y eliminación segura;
- protección de datos desde el diseño y por defecto;
- prohibición del reconocimiento o identificación biométrica automatizada.

## Datos que no deben incorporarse al repositorio público

No se deben subir a GitHub archivos que contengan:

- cédulas, firmas manuscritas o números telefónicos;
- correos personales o direcciones domiciliarias;
- audios o videos de entrevistas;
- fotografías con personas reconocibles sin autorización de publicación;
- consentimientos informados firmados;
- nóminas sin anonimizar;
- registros reales de clientes, trabajadores o establecimientos;
- historias clínicas, diagnósticos, lesiones o tratamientos;
- peso, medidas corporales, huellas o plantillas faciales;
- información de pagos, asistencias o rutinas asociada a personas reales.

## Recomendaciones para el repositorio

Se recomienda mantener dos espacios separados:

1. **Repositorio público:** documentos anonimizados, plantillas vacías, modelos, mockups y evidencias sin datos personales.
2. **Almacenamiento privado institucional:** consentimientos firmados, avales, grabaciones autorizadas, nóminas completas y demás evidencia restringida.

También se recomienda configurar un archivo `.gitignore` para impedir la carga accidental de material sensible:

```gitignore
# Evidencias sensibles o restringidas
privado/
confidencial/
consentimientos_firmados/
entrevistas/
audios/
videos/
fotografias/
transcripciones_sin_anonimizar/

# Archivos temporales
*.tmp
*.bak
*.swp
~$*
.DS_Store
Thumbs.db
```

## Control de cambios

Para conservar la trazabilidad documental, cada modificación debe registrar:

- código del documento;
- número de versión;
- fecha de actualización;
- responsable de la modificación;
- descripción breve del cambio;
- estado de revisión o aprobación.

Los nombres de archivos deben mantenerse consistentes y evitar términos ambiguos como `final`, `final2` o `definitivo_nuevo`. Se recomienda utilizar versiones explícitas, por ejemplo:

```text
A1_Protocolo_Investigacion_v3.4.pdf
A2_Instrumentos_Recoleccion_v2.7.pdf
A4_Plan_Gestion_Datos_v3.0.pdf
```
