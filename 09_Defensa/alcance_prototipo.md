# Alcance del prototipo base - FabroGym 2B

## Propósito

Este documento reemplaza los antiguos escenarios operativos de ejecución en vivo. Su función es dejar claro que el prototipo base se presenta como evidencia de apoyo para la defensa, no como eje de exposición ni como sistema productivo.

## Cobertura reportada

- RF Must cubiertos: 16/19.
- Cobertura verificada: 84.2 %.
- Comprobaciones UI: 31/31.
- Rol del prototipo: materialización parcial de requisitos priorizados.

## Requisitos fuera del prototipo base

- RF-16: entradas y ajustes de stock.
- RF-17: venta y descuento de existencias.
- RF-19: conciliación y cierre de caja.

Estos requisitos no deben presentarse como funcionalidades implementadas en el prototipo base.

## Cómo debe mencionarse en la defensa

Frase sugerida:

> El prototipo base se utiliza como evidencia de cobertura y materialización parcial de requisitos priorizados. No se realizará una ejecución operativa en vivo; se reportan resultados de alcance, verificación y coherencia con la trazabilidad.

## Qué sí puede mostrarse

- Capturas de pantalla del prototipo como evidencia visual.
- Cobertura 16/19 RF Must.
- Relación evidencia -> requisito -> verificación -> pantalla.
- Límite explícito de lo no implementado.

## Qué no debe afirmarse

- Que el sistema está productivo.
- Que existe backend definitivo.
- Que existe base de datos final.
- Que hay pasarela de pagos o facturación externa integrada.
- Que el recomendador IA está implementado.
- Que se ejecutarán dos escenarios operativos en vivo como parte obligatoria de la defensa.
